# Ant Design 6.3.5 baseline — what the theme already gives you

Shesha renders on **Ant Design v6.3.5**. This file is the *baseline authority*: what
Ant produces on its own, so a styling pass never invents a value it could have
looked up. Every number here was generated by executing Ant's own
`getDesignToken()` and per-component token functions against the `antd@6.3.5`
package — not transcribed from documentation.

Companion files:

| File | Holds | Read it |
|---|---|---|
| [ant-tokens.md](ant-tokens.md) | Every token value for all 72 Ant components (531 global + 726 component values) | **Look up one value.** It is a dictionary — never read it end to end |
| `assets/ant-6.3.5/ant-tokens.json` | The same values, machine readable | Programmatic checks |
| `assets/ant-6.3.5/shesha-theme.ts` | The upstream minimal seed theme + provenance | Only when regenerating this baseline |

## Precedence — three layers, and which wins

1. **Brand token file** (`assets/themes/<brand>.tokens.json`, default `shesha`) — **always wins.** Its `$antdTheme` block is what actually ships to the app.
2. **This baseline** — the Ant 6.3.5 default. Governs anything the brand file does not name.
3. **Nothing else.** Never invent a hex, px, radius or shadow. If it is in neither layer, it is an Ant default — look it up in `ant-tokens.md`.

The upstream seed theme (`shesha-theme.ts`) overrides only three seeds —
`colorPrimary` `#003BB2`, `colorInfo` `#003BB2`, `colorTextBase` `#181818` — and
lets Ant derive everything else. The shipped `shesha.tokens.json` is a
**deliberate superset** of that; see the deviations table below before "fixing"
it back toward stock Ant.

## The Cobalt ramp is derived — never hand-set it

Ant computes these from `colorPrimary: #003BB2`. Setting them by hand desynchronises
the ramp from the seed:

`colorPrimaryHover` `#1F5ABF` · `colorPrimaryActive` `#002A8C` ·
`colorPrimaryBorder` `#6899D9` · `colorPrimaryBg` `#DAE6F2` · `colorLink` `#003BB2`

Text ramp derived from `colorTextBase: #181818`:
`colorText` `rgba(24,24,24,0.88)` · `colorTextSecondary` `rgba(24,24,24,0.65)` ·
`colorTextTertiary` `rgba(24,24,24,0.45)` · `colorTextQuaternary` `rgba(24,24,24,0.25)`.

**Two blues are always wrong:** `#1890FF` (unthemed Ant v4) and `#1677FF` (the Ant
v6 default Cobalt replaces). Either one in output means the theme was bypassed.

## Where the Shesha default deliberately deviates from stock Ant

These are **intentional** — the brand file is the authority, not this table's
"Ant 6.3.5" column. Listed so a styling pass recognises them as decisions rather
than drift:

| Token | Ant 6.3.5 | `shesha.tokens.json` | Why |
|---|---|---|---|
| `fontFamily` | system stack (Inter prepended upstream) | system stack, **no web font** | `$fontPolicy` — instant render on any network (government / rural deployments) |
| `fontSizeHeading1` / `2` / `3` | 38 / 30 / 24 | 24 / 20 / 16 | 38px and 30px are almost never right inside an application |
| `colorBgLayout` | `#F5F5F5` | `#F8F8F9` (Athens Grey) | Brand canvas |
| `colorBorder` | `#D9D9D9` | `#D0D5E0` | Cooler line to sit under Cobalt |
| `colorSuccess` | `#52C41A` (2.27:1) | `#007E00` (5.27:1) | Ant's green fails WCAG AA |
| `colorError` | `#FF4D4F` (3.27:1) | `#D61111` (5.32:1) | Ant's red fails AA as text |
| `colorWarning` | `#FAAD14` (1.90:1) | `#FF6600` (2.94:1) | Improved, still fill-only — see below |
| `boxShadow` | Ant's 3-part elevation | `0 1px 4px rgba(0,0,0,0.08)` | Border-forward: structure comes from the hairline |

Anything **not** in this table and not in the brand file takes the Ant default.

## Accessibility — measured, on `#FFFFFF`

Cobalt is a genuine improvement over the Ant default: `#003BB2` measures
**9.26:1** against white in both directions (AAA as text *and* as a fill carrying
white text), where Ant's `#1677FF` measures 4.10:1 and fails. No separate link or
button colour is needed.

The Shesha default already hardens three of the five Ant defaults that fail
WCAG 2.2 AA. **Two still fail** — know which:

| Brand token | Measured on white | Verdict |
|---|---|---|
| `palette.brand.primary` `#003BB2` | 9.26:1 | AAA |
| `palette.ink.primary` `#181818` | 17.76:1 | AAA |
| `palette.ink.muted` `#333333` | 12.63:1 | AAA |
| `palette.semantic.success` `#007E00` | 5.27:1 | AA — hardened from Ant's 2.27:1 |
| `palette.semantic.danger` `#D61111` | 5.32:1 | AA — hardened from Ant's 3.27:1 |
| `palette.semantic.warning` `#FF6600` | 2.94:1 | **fails as text and as a white-text fill** — amber cannot carry white text at any usable saturation. Use it as a border/icon accent; warning *text* takes the badge `fg` `#E65100` on `#FFF8E1` (3.57:1 — large text / bold only) |
| `palette.lines.borderStrong` `#D0D5E0` | 1.47:1 | **fails** WCAG 2.2 non-text contrast (control boundaries need 3:1) |
| `palette.ink.soft` `#9BA3B8` | 2.52:1 | Placeholder only — never the carrier of meaning |
| `palette.ink.faint` `#C0C5D0` | 1.73:1 | Decorative only |

Status badge foregrounds on their own tint all pass AA: info 8.28:1 · draft
11.27:1 · error 5.75:1 · success 4.69:1 (warning 3.57:1, large/bold only).

**Where a deployment must certify AA**, harden per-app rather than changing the
default brand: `colorBorder` → `#8C8C8C` (3.36:1) and `colorTextQuaternary` →
`rgba(24,24,24,0.55)` (4.53:1). Both move the app further from stock Ant, so
they are opt-in per deployment. The upstream hardened set is in
`assets/ant-6.3.5/shesha-theme.ts` (`sheshaThemeAccessible`).

Non-negotiable regardless of theme:

- **Colour is never the only carrier of meaning.** Every semantic colour pairs with an icon or text label. Required fields, validation states and status chips all carry a text equivalent.
- **Focus is always visible** — 2px Cobalt outline on every interactive element, never removed.
- **Read-only is not disabled.** Read-only keeps full `colorText` contrast because it is *content*; disabled uses `colorTextDisabled` with a non-interactive cursor. Rendering read-only data in the disabled style is a defect.
- **State never shifts font weight.** Weight changes glyph width and shifts the layout — active/selected states use colour, background, border or an indicator bar.
- **Nothing a person must read goes below 14px.** 12px is for help text, timestamps, metadata and chips only.
- Layouts survive 200% text resize; allow 30–40% text expansion over English for localisation.

## Posture the baseline assumes

- **Top-aligned.** Never centre a form or table vertically — pages grow downward as data grows.
- **Density over whitespace.** This is a data tool; tables and forms are allowed to be dense. Compact density reduces padding and row height, never type size.
- **One primary action per screen.** Secondary actions stay visually quieter.
- Whitespace separates sections before borders do; body prose sits at 60–80 characters per line (table cells and field values exempt).
- Tabular figures on every column of numbers.
- Motion signals state change, never decoration: 0.1s fast · 0.2s standard · 0.3s slow, `cubic-bezier(0.645,0.045,0.355,1)`. Respect `prefers-reduced-motion`.
- No neumorphism, no glassmorphism, no shadows on inputs. Raised elevation is for dropdowns, modals, popovers and floating buttons only.

Ant breakpoints: `screenXS` 480 · `screenSM` 576 · `screenMD` 768 · `screenLG` 992
· `screenXL` 1200 · `screenXXL` 1600. Tables never truncate a value out of
existence — if a column cannot be shown at a breakpoint, move it into a detail
view rather than dropping it.

## What the theme owns vs what the form owns

This is the line that decides whether a value belongs in a v7 style block:

**The app-level `$antdTheme` owns control-level appearance** — button fill and
text colour, input border and focus ring, table header tint and row hover/selected,
radius, control height, base font and semantic colours. Never re-declare these
per component. A per-button `background.color: "#003BB2"` freezes Cobalt, breaks
the App Themer, and drifts the moment the brand changes. Brand primary on a
button comes from the theme, never from the button. Set the component and its
*behavioural* props and let it inherit.

**v7 style blocks own composition the theme cannot express** — page ground, card
and panel surfaces with their hairlines, section header strips, rail widths and
flex splits, density, status chips, header bands. These are required, not
optional: [R-042] ships no form unstyled and
`shesha-form-edit/scripts/validate-styledness.js` fails a form whose visual
components are under 40% styled or which declares no typography at all.

Values inside a v7 block still resolve from the brand token file via
[token-to-prop-mapping.md](token-to-prop-mapping.md) — never a literal typed from
memory, and never a value this baseline shows the theme already provides.

## Output checks

Before returning styled markup:

- No `#1890FF`, no `#1677FF` anywhere.
- No control-level value (button fill, input border, focus ring, table header tint, control height, base radius) re-declared per component — those come from the app theme.
- Every hex in a style block traces to a key in the brand token file.
- Placeholder text is never a field's only label.
- Read-only data is not rendered in the disabled style.
- Forms and tables top-aligned; one primary action per screen.
- No font-weight change used to signal active/selected.
- No type below 14px on anything a person reads.
- Every semantic colour paired with an icon or text label.

## Regenerating

`assets/ant-6.3.5/shesha-theme.ts` is the upstream seed source. If a seed token
is added to or removed from it, or Ant is upgraded past 6.3.5, then
[ant-tokens.md](ant-tokens.md) and `ant-tokens.json` are stale and must be
regenerated by re-executing `getDesignToken()` against the new package — and the
deviations table above must be re-checked against the brand files. Keep theme
changes rare and deliberate for that reason.
